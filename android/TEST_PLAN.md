# Android 통합 테스트 계획

이 문서는 Android 앱의 실제 기기 검증 절차다. CI의 Kotlin/C++ 컴파일 및 Lint 통과만으로 아래 항목이 검증된 것으로 간주하지 않는다.

## 준비
- Android 8.0(API 26) 이상 기기 또는 에뮬레이터
- Android Studio에서 `android` 디렉터리 열기
- 개발 브랜치에서는 APK 산출물을 만들지 않는다. 최종 통합 검증 단계에서만 릴리스 APK를 생성한다.

## 테스트 케이스

| ID | 영역 | 절차 | 기대 결과 |
|---|---|---|---|
| AND-001 | 최초 실행 | 앱 데이터가 없는 상태로 앱 실행 | 새 알이 생성되고 초기 포켓몬 선택이 표시된다 |
| AND-002 | 저장/복원 | 초기 포켓몬 선택 후 돌봄, 앱 종료 및 재실행 | 종, 레벨, 돌봄 수치가 저장된 상태로 복원된다 |
| AND-003 | 강제 종료 | 돌봄 직후 앱을 강제 종료하고 다시 실행 | 마지막으로 저장된 상태가 손실 없이 복원된다 |
| AND-004 | 오프라인 성장 | 앱을 종료한 채 10분 이상 경과 후 재실행 | 경과 시간이 공통 엔진 규칙에 따라 반영된다 |
| AND-005 | 오프라인 상한 | 14일을 초과한 경과 시간을 가정해 엔진 테스트 실행 | 오프라인 진행은 최대 14일로 제한된다 |
| AND-006 | 수면 중 오프라인 | 펫을 재운 뒤 앱 종료, 일정 시간 후 재실행 | 에너지 회복 및 수면 중 돌봄 수치 감소 규칙이 적용된다 |
| AND-007 | 진화 | 진화 조건을 충족한 뒤 앱에서 진화 실행 | 앱의 펫 종이 변경되고 저장된다 |
| AND-008 | 1×1 위젯 | 홈 화면에 1×1 위젯 추가 | 펫 이미지와 레벨이 표시되고 터치 시 앱이 열린다 |
| AND-009 | 2×2 위젯 | 홈 화면에 2×2 위젯 추가 | 펫 이미지, 레벨, 배고픔·에너지·청결도·행복도가 표시된다 |
| AND-010 | 위젯 갱신 | 앱에서 돌봄 행동 수행 후 홈 화면 확인 | 위젯 값과 이미지가 최신 펫 상태로 갱신된다 |
| AND-011 | 백그라운드 갱신 | 앱을 닫고 WorkManager 실행을 기다린 뒤 확인 | 위젯이 갱신된다. 단, Android 절전 정책에 따른 지연은 허용한다 |
| AND-012 | 진화 이미지 | 위젯 설치 상태에서 진화 실행 후 위젯 갱신 | 다음 위젯 갱신에 진화한 종의 스프라이트가 표시된다 |
| AND-013 | 백업 | 앱 설정에서 ZIP 백업 생성 | 저장 파일이 ZIP으로 내보내진다 |
| AND-014 | 복원 | 초기화 또는 다른 테스트 데이터 후 ZIP 복원 | 저장 상태가 복원되고 앱과 위젯이 복원 상태를 표시한다 |

## 결과 기록

각 케이스를 실제 기기에서 실행한 뒤 다음 중 하나로 기록한다.
- 통과: 기대 결과와 일치
- 실패: 재현 절차, 기기/Android 버전, 로그 첨부
- 보류: 기기 또는 테스트 조건 미확보

## 현재 검증 경계

- GitHub Actions의 Android 컴파일, 네이티브 C++ 컴파일, Lint 및 단위 테스트 태스크는 자동 검증 영역이다.
- 공통 C++ 엔진의 오프라인 진행(14일 상한, 수면 규칙)과 저장/복원은 호스트 테스트 대상이다.
- 위젯 런처 표시, WorkManager 실제 실행 시점, 파일 선택기를 통한 백업/복원, 앱 강제 종료 후 동작은 Android 기기 또는 에뮬레이터에서 별도 확인해야 한다.
- 실제 기기 테스트 전에는 위 항목을 통과했다고 보고하지 않는다.
